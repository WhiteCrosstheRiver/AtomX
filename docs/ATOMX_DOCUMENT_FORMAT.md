# AtomX 原生文档 v9

`.atomx` 保存一个当前结果及其创作显示设置，不要求额外运行库。文件不是 Materials Studio 的 XSD，也不是跨软件交换格式。

## 保存内容

- 元素类型、笛卡尔位置、晶胞矩阵、PBC、原点和注释。
- 显式键：两端索引、周期映像、单/双/三键级和芳香键，以及键显示设置。编码 4 代表芳香键（1.5），不是四重键。
- 原子标量/向量属性、指定颜色、属性分量名称、全局属性与科学数据表。缺失值 NaN 原样保留。
- 运动分组复用科学数据块：`AtomX.MotionGroup` 标量列是各原子所属组的正整数编号（0/NaN 为未分组），`AtomX.MotionGroups` 表的 `ID`、`Name` 两列保存名称。取消分组保留原子，新绘制原子默认未分组；没有模拟刚体求解语义。
- 创作模式、单视口相机、原子大小/形状与逐类型外观、选择、工具/目标元素/键级/连续开关、环大小、片段库项键与连接点索引、属性面板页。
- 隐藏标记、默认及逐原子标签、文字样式与数量上限。
- 默认及逐原子显示预设（原有外观、线、棒、球棒、CPK）和共享半径、比例、线宽；逐原子覆盖跟随删除后的原子身份重排。
- 默认及逐原子着色规则：来源/元素/自定义色、数值渐变与整数分类，保存范围、渐变及色标选项。
- 距离、角度、扭转角的测量端点、活动标记及可见性；读数由恢复后的实际坐标计算。

保存的是管线计算后的结构。修改器步骤、撤销/重做历史、工作区快照、其他标签及外部自定义网格文件不包含在文档中。重开建立一个新编辑基线。

## 编码与校验

开头为 8 字节 ASCII `ATOMXDOC`，随后为小端 `uint32` 版本号 9。数值使用小端定宽整数和 IEEE 浮点；布尔为 0/1 的 `uint8`。字符串为 `uint64` 字节长度和 UTF-8 内容，数组为 `uint64` 元素数和元素数据。Atom 为三个 float32 坐标加 uint32 类型索引（16 字节）；键的端点、映像和键级分别写入，不含 C++ 对齐填充。

v2 在标签块之后、`DONE` 之前增加一个 int32 环大小（4–6），工具枚举增加 Ring=5，键级允许芳香编码 4。v3 在环大小后追加片段库项键字符串与 int32 连接点索引（0–511），工具枚举增加 Fragment=6。仍读取 v1/v2：v1 环大小默认为 6，不能声明环工具或芳香键；v2 不能声明片段工具；旧文档片段默认为 `builtin/methyl`、连接点 1。v4 在片段连接点之后追加默认样式 uint8（0 原有外观、1 线、2 棒、3 球棒、4 CPK），球半径、棒半径、CPK 比例、线宽四个 float32，以及 uint64 覆盖数量和每项 int32 原子索引 / uint8 样式。旧文档默认保持原有外观；仍读取 v1/v2/v3。旧版本程序不能读取新写出的 v4 文档。

自定义片段库用普通 `.atomx` 文件保存：title 为名称、basedOn 为库名、selection 中唯一末端原子为连接点。创建中引用的自定义库文件不嵌入普通结构文档；缺少对应本机库项时不提供放置预览，需重新选择。已经放置的原子与键仍完整保存在结构文档内。

数据块依次为类型、原子、晶胞/PBC/原点/注释、键/键样式、原子颜色、科学属性与表、创作视图/工具/逐类型样式、隐藏/标签。末尾为 ASCII `DONE`。准确字段顺序以 `src/creation_document.hpp` 为准；修改格式需更新版本并提供对应读取分支。

读取分配前检查声明长度与剩余字节，校验索引、键级、有限坐标和视图设置，拒绝未知版本、截断或额外尾随内容。原生文档要求全量读取，超过原子预算时报错，用户须提高预算后重开。读写每 1 MiB 检查取消状态。

界面保存异步执行，先写同目录临时文件，成功后通过原子替换发布，避免失败覆盖已有文档。创作 Ctrl+S 首次选择保存路径，保存成功后该标签记住文档位置，后续 Ctrl+S 更新该文件。Save As 可另选路径；各标签独立保存文档位置。

v5 在样式覆盖块后追加 uint8 测量可见性、int32 活动标记索引（-1 表示无活动标记）、uint64 标记数量及每项 uint8 点数 / 四个 int32 原子索引。点数为 2/3/4，未用索引为 -1，实际索引互异且有效；最多 256 项。工具增加 Distance=7、Angle=8、Torsion=9。数值由当前实际笛卡尔坐标计算，不持久化浮点读数。删除测量端点会移除对应标记，其余索引重排。读取 v1–v4 时默认无测量标记。旧程序不能读取 v5。

v6 在测量块后追加标签属性字段：每条标签含 int32 有效数字（1–9）、uint64 字段数（最多 16）及每项 uint8 字段类型 / 字符串属性名。先写默认标签，再写 uint64 稀疏标签数量和各 int32 原子索引的字段。旧版本的标签文字形式保留。

v7 在标签字段之后追加默认着色规则、uint64 稀疏覆盖数量及每项 int32 原子索引 / 着色规则。规则依次为 uint8 方式（0 来源、1 元素、2 自定义、3 属性渐变、4 分类编号）、三个 float32 RGB、属性名字符串、两个 float64 区间端点、int32 渐变编号（0–9）、uint8 反转 / 离散 / 图例标记；每规则固定部分 44 字节加属性名 UTF-8 长度。验证有限且有序端点、RGB 范围、方式、属性名及覆盖索引，拒绝重复覆盖。颜色规则不覆盖科学数据；未保存展开后的 GPU 颜色数组。继续读取 v1–v6，默认来源颜色。旧程序不能读取 v7。

v8 在着色规则后追加 uint8 自动更新氢开关；读取旧版本默认关闭。

v9 在自动氢开关后追加键标签块：默认规则（文字字符串、int32 有效数字、uint64 属性数及每项 uint8 字段），uint64 局部覆盖数及每项键身份 / 规则，float32 字号、四个 float32 RGBA、uint8 粗体 / 可见性、int32 屏幕上限。字段 0–4 分别为 Length、BondOrder、端点编号、物理 Midpoint、Image；最多五项互异字段。键身份为两个 uint32 端点及三个 int64 周期像，使用正反向中的字典序较小者；不包括键级，改变键级保留标注。局部覆盖最多 2000，要求匹配当前显式键且身份唯一。屏幕上限 1–2000、默认 500；缓存与动态数值不持久化。继续读取 v1–v8，默认无键标签；旧程序不能读取新写出的 v9。
